# راهنمای به‌روزرسانی زیتون فدک

ساختار پروژه عمداً چندبخشی است تا بتوان فروشگاه، پنل حسابداری و سرور را جداگانه تغییر داد، بدون اینکه یک فایل عظیم و درهم ساخته شود.

## هر تغییر را کجا انجام بدهم؟
- رابط فروشگاه و ساختار HTML: `apps/storefront/index.html`
- رنگ‌ها، اندازه‌ها و واکنش‌گرایی فروشگاه: `apps/storefront/assets/css/storefront.css`
- منطق خرید، سبد، نمایش محصولات و فرم‌های فروشگاه: `apps/storefront/assets/js/storefront.js`
- تصویرسازی‌های SVG و اجزای گرافیکی: `apps/storefront/assets/js/illustrations.js`
- اتصال فروشگاه به سرور: `apps/storefront/assets/js/api.js`
- آدرس سرور و نسخه‌ی رابط: `apps/storefront/config.js`
- رابط حسابداری: `apps/panel/index.html`
- مدیریت سفارش‌های سایت: `apps/panel/orders.html` با ظاهر و منطق جداگانه در `assets/css/orders.css` و `assets/js/orders.js`
- ظاهر پنل: `apps/panel/assets/css/panel.css`
- منطق اصلی پنل و ذخیره‌ی اطلاعات: `apps/panel/assets/js/panel.js`
- انیمیشن‌ها و نمودارهای نمایشی پنل: `apps/panel/assets/js/panel-effects.js`
- API، اعتبارسنجی سفارش و منطق کسب‌وکار: فایل‌های `backend/app/`
- تغییر شکل جداول دیتابیس: یک مهاجرت جدید Alembic در `backend/migrations/versions/`

## روش امن انتشار نسخه‌ی جدید
1. قبل از تغییر، شاخه‌ی جدید بساز؛ مستقیم روی `main` کار نکن.
2. تغییر را کوچک و مشخص نگه دار و هر دو اندازه‌ی موبایل و دسکتاپ را بررسی کن.
3. تغییرات API را با آزمون‌های `backend/tests/` پوشش بده. بررسی‌های GitHub Actions باید سبز شوند.
4. قبل از استقرار نسخه‌ی جدید، از پایگاه داده نسخه‌ی پشتیبان بگیر.
5. نسخه را منتشر کن؛ سپس `/health`، بازشدن فروشگاه، `/panel/`، ثبت سفارش آزمایشی و ذخیره/بازیابی پنل را بررسی کن.

## به‌روزرسانی نصب Docker
روی سروری که نسخه‌ی مخزن را دریافت کرده است:
```bash
./scripts/update.sh
```
این اسکریپت ابتدا از دیتابیس نسخه‌ی پشتیبان می‌گیرد، سپس فقط با fast-forward کد را دریافت می‌کند و سرویس‌ها را دوباره می‌سازد. داده‌ی Postgres در volume مستقل می‌ماند و با ساخت دوباره‌ی کانتینر حذف نمی‌شود.

## نکات مهم درباره‌ی داده‌ها
- فایل `.env` و هر نوع کلید خصوصی نباید وارد GitHub شوند.
- نسخه‌ی پشتیبان شامل اطلاعات مشتریان است؛ آن را خصوصی و با دسترسی محدود نگه دار.
- قیمت‌های داخل seed فقط داده‌ی اولیه هستند؛ پس از ساخته‌شدن کاتالوگ در دیتابیس، تغییر seed قیمت‌های قبلی را خودکار بازنویسی نمی‌کند. تغییر قیمت‌های زنده باید از طریق پنل مدیریتی/رابط مدیریت امن انجام شود.
- برای اضافه یا تغییر ستون‌های دیتابیس، فایل migration جدید بساز. یک نسخه‌ی migration که قبلاً روی دیتابیس اجرا شده است را دستکاری نکن.
- اگر نام یا شناسه‌ی محصول عوض شد، شناسه‌های موجود در سفارش‌ها و داده‌های پنل را هم بررسی کن.
- پس از تغییر API، فرانت‌اند باید با همان قرارداد API سازگار بماند یا هر دو بخش هم‌زمان به‌روزرسانی شوند.
