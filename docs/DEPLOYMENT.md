# راه‌اندازی زیتون فدک

## پیش‌نیاز
یک سرور Linux با Docker Engine و افزونه‌ی Docker Compose، دامنه‌ی کنترل‌شده توسط مالک، و دسترسی برای تنظیم DNS لازم است. این مخزن به‌تنهایی یک هاست ابری را ایجاد نمی‌کند؛ فایل‌های استقرار برای سروری هستند که خودت تهیه/اجازه‌ی استفاده از آن را داری.

## راه‌اندازی اولیه
1. مخزن را روی سرور clone کن.
2. فایل نمونه‌ی تنظیمات را کپی کن:
   ```bash
   cp .env.example .env
   ```
3. در `.env` یک رمز تصادفی بلند برای Postgres و یک توکن خصوصی با حداقل ۳۲ نویسه تنظیم کن. همان رمز دیتابیس باید با مقدار داخل `DATABASE_URL` هماهنگ باشد. فایل `.env` را ارسال یا commit نکن.
4. اجرا:
   ```bash
   docker compose up -d --build
   ```
5. آزمون اولیه:
   - فروشگاه: `http://SERVER:8080/`
   - پنل: `http://SERVER:8080/panel/`
   - سلامت API: `http://SERVER:8080/health`
   - مستندات API: `http://SERVER:8080/docs`
   - سفارش‌های اینترنتی (پس از تنظیم کلید مدیریتی): `http://SERVER:8080/panel/orders.html`

## دامنه و HTTPS
برای یک دامنه‌ی عمومی، DNS را به سرور اشاره بده، از پیکربندی مناسب Caddy با دامنه‌ی واقعی استفاده کن و `ALLOWED_ORIGINS` را به مبدأهای دقیق مجاز تغییر بده. پورت‌های 80 و 443 باید طبق محیط میزبان قابل دسترس باشند. از انتشار مستقیم پورت 8000 API روی اینترنت خودداری کن.

## قبل از استفاده‌ی واقعی
این نسخه یک پایه‌ی قابل توسعه است و هنوز به معنی آماده‌بودن تمام عملیات تجاری برای مشتری عمومی نیست:
- پنل فعلی برای سازگاری از یک توکن مشترک استفاده می‌کند؛ آن را به‌عنوان سامانه‌ی احراز هویت کامل چندکاربره در نظر نگیر. برای استفاده‌ی جدی باید هویت مستقل کارکنان، نقش‌ها، نشست‌های محدود و گردش بازیابی دسترسی پیاده‌سازی و آزموده شود.
- درگاه پرداخت آنلاین عمداً غیرفعال است تا اطلاعات پذیرنده و قرارداد رسمی درگاه مشخص شود؛ هیچ درخواست پرداختی نباید به‌عنوان پرداخت موفق تلقی شود تا اعتبارسنجی سمت سرور انجام شود.
- اتصال کارت‌خوان فیزیکی تنها با CSV معتبر از بانک/ارائه‌دهنده یا API/وب‌هوک رسمی آن امکان‌پذیر است. کلید امضای وب‌هوک را محرمانه نگه دار.
- ارسال پیامک و کد یک‌بارمصرف فعلاً پیاده‌سازی نشده است.
- متن‌های تماس، نشانی، ساعات پاسخ‌گویی و قیمت‌ها را با اطلاعات تأییدشده‌ی کسب‌وکار جایگزین کن.
- آزمون‌های خودکار را روی CI اجرا کن و یک نسخه‌ی پشتیبان قابل بازیابی را قبل از انتشار بررسی کن.

## پشتیبان‌گیری و بازیابی
- ساخت نسخه‌ی پشتیبان: `./scripts/backup.sh`
- بازیابی یک فایل SQL: `./scripts/restore.sh backups/FILE.sql` (داده‌های جاری را جایگزین می‌کند و نیاز به تأیید دارد).
- داده‌ی واقعی مشتریان را در چت یا در فایل‌های قابل‌انتشار قرار نده.
